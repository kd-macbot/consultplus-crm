# Мониторинг на грешките

## Какво решава

Досега, когато при колега гръмне нещо, никой не научаваше — освен ако човекът
не се обади. `ErrorBoundary` показва екран с извинение, но следата остава само
в неговата конзола и изчезва при затваряне на таба.

Сега всяка неуловена грешка отива в Sentry: стектрейс, версия на билда,
браузър, кой екран е бил отворен.

## Включване (веднъж)

Изключен е, докато няма DSN. Без него SDK-то **дори не се качва в bundle-а** —
Vite замества `import.meta.env.VITE_SENTRY_DSN` с `undefined` при билда и
целият блок отпада като мъртъв код.

1. Профил в [sentry.io](https://sentry.io) → нов проект → платформа **React**.
   ⚠️ **Избери ЕС региона** (хостът на DSN-а трябва да съдържа
   `ingest.de.sentry.io`, не `ingest.us.sentry.io`). Данните на фирмата са на
   български клиенти — да не пътуват до САЩ без нужда.

2. Копирай DSN-а. Той е **публичен по дизайн** — стои в JavaScript-а на
   страницата и всеки може да го види. Не е таен ключ; служи само за адрес.

3. Cloudflare Pages → Settings → Environment variables → добави
   `VITE_SENTRY_DSN` за **Production** (branch `main`).
   За dev preview (branch `dev`) сложи същия или отделен проект — двете среди
   се различават по тага `environment` (`production` / `dev`).

4. Нов деплой. Проверката, че работи, е по-долу.

## Проверка, че работи

В конзолата на браузъра:

```js
setTimeout(() => { throw new Error('тест на мониторинга') }, 0)
```

До минута грешката трябва да се появи в Sentry. Ако не се появи:
- виж дали `VITE_SENTRY_DSN` е стигнала до билда (в Network таба трябва да има
  заявка към `ingest.de.sentry.io`);
- ad-blocker в браузъра често блокира Sentry — пробвай в друг профил.

## Лични данни

Системата работи с РЕАЛНИ данни (имена, ЕГН, телефони, хонорари). Затова:

| | |
|---|---|
| **Session Replay** | ИЗКЛЮЧЕН — той записва екрана, тоест самите клиентски данни |
| **Performance tracing** | ИЗКЛЮЧЕН — не ни трябва, а мъкне URL-и |
| **IP адрес и самоличност** | НЕ се пращат (`sendDefaultPii: false`) |
| **Конзолни трохи** | ИЗКЛЮЧЕНИ — приложението логва данни в конзолата |
| **DOM трохи (кликове)** | ИЗКЛЮЧЕНИ — носят текст от екрана |
| **Мрежови трохи** | остават, но БЕЗ query string — там влизат филтри със стойности |

Всяко съобщение минава през `redact()` (`src/lib/monitoring.ts`), която маха
ЕГН, IBAN, телефони и имейли. Не разчитаме на това, че „грешките не съдържат
данни" — съобщение от Postgres спокойно връща стойността на реда, счупил
constraint.

`redact()` е покрита с тестове (`src/lib/monitoring.test.ts`). Ако я пипаш,
пусни ги.

**ЕИК НЕ се заличава** — публичен е и без него разследването на бъг става
безпредметно.

Тънкост: ЕГН и слят телефон са по 10 цифри. Разграничават се по 3-4 позиция —
при ЕГН там стои месецът (01-12, +20 за родените преди 1900, +40 за след 2000).
И в двата случая стойността излиза заличена; разликата е само в етикета.

## Кой знае кой е сгрешил

Не се праща самоличност. При 16 души в екипа обикновено се сеща кой е бил по
времето и екрана. Ако някога стане нужно, добавя се `Sentry.setUser()` — но
това е лични данни на служител и иска съзнателно решение, не подразбиране.

## Цена в bundle-а

SDK-то се зарежда **динамично**, отделно от първоначалния bundle. Докато се
зарежда, прости native handler-и трупат грешките в буфер и ги предават, щом
SDK-то е готово — нищо не се губи, но и нищо не се бави.

Критичният път расте с ~2 kB gzip (148 вместо 146). Самото SDK е 26 kB gzip в
отделен chunk.

⚠️ Тези 26 kB не са даденост. Ако някой смени `import('./sentryClient')` с
`import('@sentry/react')` и вземе целия namespace, Rollup няма как да разбере
кое ползваме и качва всичко — Replay, Feedback, tracing, profiling. Измерено:
**150 kB gzip**. Затова `sentryClient.ts` е отделен файл с ПОИМЕННИ статични
импорти и изричен списък с интеграции, а не филтриране на defaults по време на
изпълнение (то ги маха от работата, но не и от файла). Флаговете в
`vite.config.ts` (`__SENTRY_TRACING__` и т.н.) довършват отрязването.

## Ръчно докладване

За catch блокове, където се възстановяваме, но пак искаме да знаем:

```ts
import { captureError } from './lib/monitoring'

try { ... } catch (e) {
  toast.error('Записът не мина')
  captureError(e, { where: 'setCellValue', clientId })
}
```

Не слагай в `context` стойности от клиентски данни — контекстът НЕ минава през
`redact()`.
