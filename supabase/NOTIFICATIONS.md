# Известия по имейл — как се пуска

Автоматични напомняния до КОЛЕГИТЕ (не до клиенти — те са в „Съобщения“
през Mobica). Два вида на старта:

| Напомняне | До кого | Кога |
|---|---|---|
| Задачи с наближаващ или изтекъл срок | изпълнителя на задачата | всяка сутрин, ако има какво |
| Незавършен ДДС чек лист | счетоводителя и отговорника на фирмата | на избрани дати преди 14-то |

Кой получава, какво е включено и на кои дати — от страницата **Известия**
(само admin). Дневникът показва всяко тръгнало писмо.

---

## Как работи

```
GitHub Action (notify.yml, 06:15 UTC, Пн–Пт)
        │  POST /functions/v1/mail-send   { "action": "run" }
        │  header x-cron-secret: <NOTIFY_CRON_SECRET>
        ▼
Edge функция mail-send  ──► чете crm_notification_settings
        │                    чете задачи / чек лист / персонал
        │                    записва crm_notifications (status=pending)
        ▼
    Resend API  ──► имейлът ──► колегата
        │
        └─► status=sent / error обратно в дневника
```

Приложението е SPA — браузърът може да прати писмо само докато някой е
логнат. Затова спусъкът е ИЗВЪН него. Избран е GitHub Action, а не pg_cron:
провалът се вижда като червено пускане в Actions, вместо тихо да спре.

**Защита от дублиране:** всяко автоматично писмо има `dedupe_key`
(`task_due:<staff>:<дата>`) с УНИКАЛЕН индекс. Редът се записва ПРЕДИ
изпращането. Двойно пуснат Action не праща второ писмо. Ако изпращането
се провали, ключът се занулява → следващото пускане пробва пак.

## Стъпки за пускане (веднъж на среда)

### 1. Миграцията

`supabase/migration-056-notifications.sql` — първо на **dev**, после на
**prod** (SQL Editor). Идемпотентна е.

Главният ключ (`enabled`) стартира **false** — след миграцията нищо не
тръгва само, докато не го пуснеш от страницата Известия.

### 2. Resend

1. Регистрация на resend.com (безплатният план стига: ~3000 писма/месец,
   при 16 колеги това е с порядък повече от нужното).
2. Domains → Add Domain → `cplus360.com`.
3. Resend дава 3 DNS записа (SPF, DKIM, DMARC). Добавят се в **Cloudflare**
   → DNS на `cplus360.com`. Без тях писмата отиват в спам или изобщо не
   тръгват. Изчаква се „Verified“ в Resend.
4. API Keys → Create → права само за изпращане. Ключът се вижда ВЕДНЪЖ.

### 3. Edge функцията

```
supabase functions deploy mail-send --no-verify-jwt
supabase secrets set RESEND_API_KEY=re_...
supabase secrets set MAIL_FROM="Consult Plus 360 <noreply@cplus360.com>"
supabase secrets set NOTIFY_CRON_SECRET=<дълъг случаен низ>
```

(деплойва се ръчно през Dashboard, както swift-task и mobica-send)

`--no-verify-jwt` + собствена проверка вътре: или admin JWT (от
страницата), или `x-cron-secret` (от Action-а). Друг не минава.

Адресът в `MAIL_FROM` трябва да е от верифицирания домейн.

### 4. GitHub secrets

Settings → Secrets and variables → Actions:

| Secret | Стойност |
|---|---|
| `SUPABASE_FUNCTIONS_URL` | `https://<project-ref>.supabase.co/functions/v1` (PROD) |
| `NOTIFY_CRON_SECRET` | същият низ като в стъпка 3 |

### 5. Имейлите на колегите

Персонал → всеки колега трябва да има попълнен **Имейл**. Без него
страницата Известия го показва с предупреждение и той не получава нищо.

### 6. Проверка (в този ред)

1. **Известия → Настройки → Пробно писмо** — доказва, че Resend и DNS-ът
   работят.
2. **Пусни сега (пробно)** — dry run: показва точно какви писма БИХА
   тръгнали днес, без да праща и без да пише в дневника.
3. **Пусни сега (наистина)** — прави го за истина, но само когато го
   натиснеш.
4. Чак когато трите минат — вдигни главния ключ и остави Action-а.

Actions → „Известия по имейл“ → Run workflow има отметка `dry_run` —
същият пробен режим, но от името на cron-а (проверява и secret-ите).

## Лични данни

Писмата излизат извън системата и остават в лога на Resend. Съдържат само
**имена на фирми, заглавия на задачи и срокове** — колкото и вътрешният
екран. НЕ добавяй ЕГН, лични карти, IBAN или хонорари.

Всеки колега може да бъде изключен поотделно (Известия → „Кой получава“ →
отметката), без да му се пипа профилът.

## Ако нещо не тръгне

| Симптом | Причина |
|---|---|
| Action-ът е зелен, но няма писма | главният ключ е изключен — отговорът казва `skipped` |
| „RESEND_API_KEY не е настроен“ | secret-ът липсва на ТОЗИ Supabase проект (dev и prod са отделни) |
| Писмата отиват в спам | DNS записите не са верифицирани в Resend |
| Колега не получава | няма имейл в Персонал, или е с изключена отметка, или няма какво да му се прати |
| „Невалиден токен“ от страницата | сесията е изтекла — презареди |
| Второ писмо за същия ден | не би трябвало — виж `dedupe_key` в дневника |
